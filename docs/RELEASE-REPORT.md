# Functional release report

Date: 2026-11-20. This replaces the three-tool static preview with a Next.js application while retaining original preview source in `legacy-preview/`.

## Completed and verified

- 44 dedicated static tool routes; 31 real local processing workflows; unavailable tools refuse uploads instead of simulating jobs.
- Configurable Paperly brand; original visual assets; searchable categorized directory, public pages, account dashboard and local workflow presets.
- PDF.js page rendering and navigation; additive editor; tool settings; validated outputs; multi-output ZIP; cancellation and errors.
- Firebase Paperly Web app registered in project `parperly`. Email/password and Google providers are enabled. The official GitHub Pages domain was added to authorized domains with the user's explicit confirmation.
- 24 automated tests pass: manipulation invariants, invalid ranges/types/size, forms, annotations, bookmark references, ownership/download predicates and settings allowlists.
- Browser verification: merge and downloaded 6-page output order, editor export and text preservation, splitting into 3 independently parseable PDFs in a downloaded ZIP, 3-page PNG export, and a two-step rotate/watermark workflow.
- Real Firebase registration/password sign-in smoke test passed; disposable test identity deleted. No verification/reset emails were sent during this test.
- Frontend and backend TypeScript checks pass. Next.js export succeeds. Production dependency audit reports zero known vulnerabilities after updating Zod and overriding vulnerable transitive gRPC versions.

## Material limits

This is not the complete production SaaS from the master brief. Full corpus/fidelity testing, encrypted PDFs, mobile device QA, complete French localization, editable Office conversion, OCR, hard resource isolation, cloud jobs/presets, billing and operational readiness are incomplete. See FEATURE-MATRIX.md for mode-specific limitations.

The backend is disabled by default. It must not be publicly enabled until Redis/private storage/identity configuration, native engine deployment, distributed crash recovery/idempotency, retention race tests, per-job isolation and API integration tests pass. Its current one-output adapter supports only a subset of tools.

## Validation commands

`npm test`, `npm run typecheck`, `npm run typecheck:server`, `npm audit --omit=dev`, `NEXT_PUBLIC_BASE_PATH=/parperly npm run build`.

`RUN_LIVE_AUTH_TEST=1 node tests/firebase-auth.integration.mjs` creates and deletes a disposable Firebase test identity; it does not exercise Google OAuth or email delivery. Test fixture PDFs are generated by `npm run fixtures` and contain only synthetic content.
